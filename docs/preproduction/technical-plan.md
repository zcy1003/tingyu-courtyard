# 听雨小镇 · 技术与实施计划

状态：本文件保留开发准备时的技术设计。用户已授权实现，当前成果见 [交付报告](../delivery-v0.1.0.md)。实际模块采用 `game/src/` 中按职责划分的平铺文件，未创建不含代码的目录结构。

## 已选择并锁定的工具

| 组件 | 版本 | 用途 |
| --- | --- | --- |
| Node.js | 本机 24.18.0 | 开发工具执行环境 |
| npm | 本机 11.16.0 | 安装依赖与锁定版本 |
| Three.js | 0.186.1 / r186 | 新游戏渲染、场景图与 glTF 加载 |
| Rapier compat | 0.21.0 | 预备角色胶囊、静态碰撞与运动学控制器 |
| Vite | 8.3.4 | 开发服务器、模块构建与静态发布 |
| TypeScript | 7.0.2 | 严格类型检查 |
| @types/three | 0.186.0 | 与新 Three.js 同代类型声明 |
| @types/node | 24.19.2 | Node 24 系列开发工具类型 |

依赖版本来自本次实际 npm registry 查询，精确版本写入 `package.json`，传递依赖和校验值写入 `package-lock.json`。没有升级本机全局 Node/npm。安装使用 `--ignore-scripts`，通过实际构建确认需要的本机二进制可用。

选择普通 TypeScript 模块和 Three.js WebGLRenderer；首版没有需要引入 UI 框架的业务复杂度。面向 WebGL2 浏览器。Rapier 使用 compat 发行包，需等待异步初始化，再创建物理世界；控制器参数在灰盒时验证。

## 工程边界

```text
index.html / src/ / vendor/       旧雨夜微缩小院与 r160 构建基线
scripts/build.py / serve.py      旧版构建与预览
package.json / package-lock.json 新工具链与依赖锁
vite.config.ts / tsconfig.json   新游戏构建与类型检查
game/index.html                 目前只有静态环境验证页
game/src/                       后续运行时代码；目前仅 Vite 类型声明
game/public/assets/             后续模型、纹理、音频（按需建立）
scripts/check-preparation.mjs    准备资料与依赖加载验证
docs/preproduction/             设计、规格、报告和原型清单
yuanxingtu/                      用户提供的五张参考图
.cache/                         本机缓存，不进入 Git
dist/game/                      新构建产物，不进入 Git
```

Vite 的根目录设为 `game/`，生产输出是 `dist/game/`，不会把历史档案和原型图自动复制为游戏资源。根目录旧页面仍由 Python 流程维护。

正式编码时拟划分：

| 模块 | 职责与约束 |
| --- | --- |
| `app/` | 启动、加载状态、更新循环、暂停和资源释放 |
| `render/` | 渲染器、灯光、色彩、画质、尺寸变化与统计 |
| `world/` | 地图数据、区域构建、地面、河岸、桥、建筑实例与环境边界 |
| `assets/` | 程序化构件工厂、共享材质、GLB 加载与资源缓存 |
| `player/` | 输入、角色移动、可见模型、动画状态与安全复位 |
| `physics/` | Rapier 初始化、静态碰撞体、胶囊控制器、地面与斜坡查询 |
| `camera/` | 跟随、拖拽、缩放、碰撞避障和室内处理 |
| `ui/` | 开始、操作提示、暂停/帮助、画质与复位 |
| `config/` | 世界尺度、速度、镜头与画质参数 |

这些模块目前只在文档中定义；不先写空类或大批占位游戏代码。

## 更新与碰撞规则

- 固定 60 Hz 物理步长，输入采样与渲染解耦；限制累计补步次数，恢复页面后不补算长时间离线位移。
- 归一化水平输入，相机相对方向转换为世界方向；碰撞先解算，随后更新角色可见位置、动画和镜头。
- 胶囊参数初值半径 0.28 米、总高 1.65 米，Rapier 圆柱部分半高约 0.545 米；以最终模型双脚和头顶校正。
- 设置斜坡限制、地面吸附和小台阶；坡道碰撞与可见台阶共存。参数需真实行走测试后确定。
- 河岸、围墙和世界边界用简化静态碰撞体；远景山不创建高密度物理网格。
- 镜头避障采用体积检测或多射线近裁面近似，滤除玩家本体/微小草叶，恢复距离用阻尼避免抖动。
- 生命周期清理包含监听器、动画帧、材质/纹理/几何、Rapier world；支持重复启动而不泄漏。

## 旧代码复用评估

| 旧实现 | 处理决定 |
| --- | --- |
| `roof`、月洞门、木格窗、桌椅、茶具、灯笼 | 复用建模思路，抽成接收父节点/材质/尺寸的模块；统一比例后重建 |
| 随机种子、共享几何、屋瓦实例化 | 保留思路；每个区域独立 seed，避免改一处导致全镇随机布局漂移 |
| 全局 IIFE 与两文件拼接 | 改成显式 ES 模块依赖与构建器返回值 |
| `batchStatic` 的世界矩阵合并 | 不能原样套用到多个变换根节点；区域实例化必须明确本地/世界矩阵，保留对象所属区域与碰撞信息 |
| Toon 梯度和深色轮廓 | 根据图 1/3 重做暖白墙与柔和材质；原视觉风格仅作造型参考 |
| 围绕微缩底座旋转的控制 | 改为角色跟随和遮挡避让 |
| 固定 12 米反射面和 Reflector 字符串改写 | 不直接迁移；新版本通过受控材质/渲染模块实现水与湿地效果 |
| `rainFloor` 中的硬编码屋顶坐标 | 雨后清晨不持续下雨；后续天气需独立的空间规则 |
| 方形展台、画面外缘 | 改为连续地面、区域边界与远景 |
| `preserveDrawingBuffer: true` | 默认关闭，截图通过专门工具或帧捕获处理 |
| `window.courtyard` 全局对象 | 后续诊断接口仅开发环境启用，生产不暴露可修改世界对象 |

r160 与 r186 不在同一游戏页面混载。迁移时使用新版本一致的 addons，并逐项检查色彩、灯光、材质与反射表现。

## 验收清单

- 功能：WASD/方向键、相机拖动、滚轮、Esc、复位；斜走不加速，失焦不持续移动。
- 碰撞：四方向贴墙、月洞门、茶室门、石桥/木桥、栏杆、河岸、台阶、回廊转角。
- 镜头：屋檐下、门内、桥下视线、紧贴墙、窗口缩放；不穿入墙体或近距离切穿角色。
- 路线：A 出发完整双向环游、E→H 和 G→I 往返、进入主茶室。
- 美术：三处固定机位截图，角色左右方向、建筑尺度和青绿/暖白色彩对照参考。
- 性能：记录设备、分辨率、像素比、平均/P95 帧时间、绘制调用、三角形、纹理估算；运行 10 分钟观察稳定性。
- 构建：`npm run verify`；加载首屏与全部资产无 404、无控制台异常；`dist/game/` 从静态服务可独立访问。
- 浏览器：电脑 Chrome/Edge 优先；Firefox 与其他设备列入后续兼容检查，不能提前标记为已通过。

准备阶段只能验证工具链与资料。角色移动、路线实际可达、FPS 和真实美术效果必须在后续代码存在后验收。
