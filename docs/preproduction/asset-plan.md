# 听雨小镇 · 资产制作规格

依据：[环境组件图](../../yuanxingtu/image_4.png)、[角色三视图](../../yuanxingtu/image_5.png)。本文件保留编码前的制作规格；当前成果见 [交付报告](../delivery-v0.1.0.md)。实际首版为 17 栋建筑，角色采用程序化关节模型，环境采用程序化几何与植被遮罩，没有依赖外部 GLB。

## 制作方式

建筑、桥、石板、窗棂等适合参数化生成的组件，优先由可复用的网格工厂生成。英雄资产（角色、主厅、石桥、近景柳树）的轮廓与细节单独打磨。运行时支持 glTF/GLB 模型，后续可用制作完成的 GLB 替换同名程序化资产。

角色初期可使用可替换的灰盒来验证移动，最终采用带骨骼的三维角色或质量足够的独立关节模型；角色外形必须对应图 5，避免用胶囊形或拼接方块形作为美术完成版。模型制作与动画属于正式实现阶段，不把原型图当作已经可用的 GLB。

当前没有购买或下载外部游戏资产。正式实现可以在现有 Three.js 工具链内开始；Blender/外部模型制作工具在需要精修或导入角色时另行评估，当前工具链不依赖其安装。若引入第三方资产，每项记录来源、许可证、修改记录和使用位置。

## 尺寸、坐标与命名

- 统一米制、Y 向上。建筑默认门面朝 +Z；模型变换在区域配置中显式设置。
- 建筑原点位于占地中心的地坪；角色原点位于双脚落地中心。
- 标准层高约 3.0–3.3 米；门净高约 2.2 米；栏杆约 1.0–1.1 米。
- 主门和院门按人物胶囊及镜头需求设计，不能只照抄图片中的透视宽度。
- 文件名示例：`building_tea_shop_a.glb`、`prop_water_jar_a.glb`、`player_traveler.glb`。
- 角色动画统一语义名：`idle`、`walk`；步行动画原地播放，位移由角色控制器决定。
- 角色自身左肩至右髋背带为定稿方向。装饰挂件跟随骨骼/节点，不产生穿体长摆动。
- GLB 中模型缩放尽量为 1、旋转归零，导入后验证包围盒、法线、切线、透明材质与动画轨道。

## 材质与几何策略

1. 墙、瓦、木、石、植物、陶瓷使用共享材质族；颜色变化优先使用实例颜色或材质参数。
2. 重复瓦片/花盆/柱子采用区域内实例化，实例组按空间分块，兼顾减少提交和视锥剔除。
3. 静态合并仅处理静态对象；角色、开合件、风动植物与动画灯笼保留独立生命周期。
4. 碰撞网格与可见网格独立。墙用盒体，桥面用简化坡面，人物用胶囊，复杂屋檐不逐瓦碰撞。
5. 草木优先使用 alpha test 或低复杂度实体叶簇，谨慎使用大量半透明叠层。
6. 若使用贴图，近景关键材质初定 1K–2K，普通道具 256–512；多件道具共享图集。颜色贴图与法线/粗糙度贴图明确区分色彩空间。
7. 大河面首版使用水色、波纹、简化环境反射及岸边细节。全场景平面镜反射经性能测量后再局部引入。

## 初始资源预算

以下均为优化目标，尚无游戏场景可供实测，不能当成已经达成的指标。

| 项目 | 初始预算 |
| --- | --- |
| 目标显示条件 | 电脑浏览器，1920×1080，像素比上限初定 1.5 |
| 流畅度 | 中档独显机器争取 60 FPS，提供 30 FPS 可游览的低画质档；正式验收记录具体硬件与帧时间 |
| 常规视角可见三角形 | 约 50–80 万以内，优先减少轮廓贡献很低的几何 |
| 主渲染可见绘制调用 | 约 250–350 以内；另记录阴影/后处理额外开销 |
| 角色 | 约 1–2 万三角形，少量材质，满足外形和动画后再优化 |
| 单个近景建筑 | 约 1–2.5 万三角形，远景简化 |
| 贴图驻留 | 先以约 128 MB 为预算，结合设备与实际采样修正 |
| 阴影 | 1 个主要投影光源，初设 2048 阴影图；低档降分辨率或简化投影 |

不将原型图自身的数百万像素嵌入首屏游戏资源。确认资产需求之后再制作实际模型和贴图，避免不必要的初次下载。
